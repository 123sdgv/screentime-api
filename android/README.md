# 我的数字生活 · Android 本地原型

支持 Android 10（API 29）及以上。中文原生界面使用 Kotlin 和 Compose，Room 保存每日聚合与采集覆盖区间。应用未申请联网权限。第一阶段在打开应用、从系统设置返回及手动刷新时采集；退出后的定期补采属于后续版本。

## 安装与第一次使用

1. 把交付的 debug APK 下载到 Android 手机。GitHub Actions 的同名产物是 ZIP，先解压得到 `app-debug.apk`。在文件管理器中点 APK，按系统提示仅为此次使用的安装来源允许安装，完成后可以关回。
2. 打开「我的数字生活」→「去授权」或「设置」→「打开系统权限设置」。在系统列表选「我的数字生活」，开启「允许访问使用情况」。不同品牌的菜单译名略有差异，也可直接在系统设置中搜索「使用情况访问权限」。
3. 返回应用等待补采。在微信、浏览器等普通应用里停留约半分钟，回桌面，再次打开本应用并刷新。点年度排名中的应用，点当天格子，分别核对时长与估算次数。预装应用可以在设置中打开「显示系统应用」查看。包名或图标不可见时会保留包名。
4. 连续刷新两次，已结束的会话不应重复累计。关闭网络，退出后重开，应仍能看见原有记录；撤销使用情况权限应出现引导，历史应保留。验收可截年度首页、同一 APP 的日期详情和设置页，分享前可遮住其他 APP 名称。
5. 测试版数据在应用私有目录。请保留已安装的测试版；卸载或清除存储会删除档案。不同构建环境的 debug 签名可能不同，若覆盖安装提示签名冲突，请先保留原应用，勿直接卸载。此阶段没有导入导出。

## 读数口径

- 首次授权尝试回看今天和之前六个本地日期，实际能读几天由系统决定。只有完全落在一个本地日内的系统统计桶才归入该日；跨日的整桶不按比例摊分。近期事件可补充可证实的时长及会话进入次数。重采取同一日可用的系统时长优先，重复的部分观测取更充分的值，保守保留已有记录。
- 暂停或停止、锁屏、熄屏、关机等事件截断会话。对同包多 Activity 的重叠求并集，连续切页采用 1.5 秒合并窗口，切回另一 APP 后重入单计。缺少结束事件的时长暂留未知。跨午夜和跨年按设备时区拆段；不同 APP 分屏的时长可重叠。
- “整日覆盖”是本地观测判断。前后两次成功检查相距至多 30 小时、系统事件包含前一观测点、连续区间覆盖本地日的两个午夜，才可能标为整日覆盖。可观测的权限中断、重启、时间回拨或时区变更会打断区间。厂商漏报以及两次检查间未被发现的权限变化仍可能造成误差；时区切换的边界采用保守记录。当日与首次回填通常为部分采集。
- 时长与次数分开记录。界面以灰色圆点表示未知，浅色 0 表示确认覆盖的零值，未来留白。绿色四档按同一个 APP、同一个年份、所选指标的最大已知值等比例划分。排行与总览共用系统 APP 筛选，搜索只筛排行榜；活跃日以正时长去重，全局活跃天数对日期取并集。

## 构建与验证

JDK 17、Android SDK Platform 35、Build Tools 34.0.0。在本目录运行：

```sh
./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest
```

测试包输出在 `app/build/outputs/apk/debug/app-debug.apk`。已连接的测试模拟器可运行 `./gradlew connectedDebugAndroidTest`。单测使用合成事件验证统计边界；设备测试使用隔离数据库校验关库重开，另在测试模拟器上启动系统设置应用，读取真实系统事件并检查撤权后的数据保留。模拟器测试不代表用户手机验收完成。

CI 使用标准 Linux runner，APK 产物保留 7 天。Room 的 v1 schema 在 `app/schemas/`；数据库创建不启用破坏性迁移。此分支关闭对应的 Vercel Git 自动预览，不修改线上 Next.js 路由、Redis、生产权限或数据。
